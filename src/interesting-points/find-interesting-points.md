# Interesting Points 検出アルゴリズム

マンデルブロ集合の描画結果（iteration buffer）から、拡大すると面白そうなポイント（渦巻きやミニブロの中心）を自動検出する。
実装は `peak-detector.ts`、エントリは `find-interesting-points.ts` の `findInterestingPoints`。

## 考え方

拡大したくなる点 = 「iteration の等高線がその点を取り囲んで閉じている点」= 局所的なピーク。
ミニブロは N で飽和したピーク、渦巻きの中心は有限だが高いピークで、どちらも同じ判定で拾える。
フィラメント（尾根）は 2 方向で落ちず、集合内部の広い領域は平坦なので、どちらもスコア 0 になる。

## 全体の流れ

```
iterationBuffer (Uint32Array, width×height)
  ↓
1. 画像内の値域（p1〜p99）で正規化。0 → 無効、N → 有効最大値より少し上 (normalizeIterations)
  ↓
2. summed-area table で有効画素のみの box blur を O(1) で引けるようにする
  ↓
3. stride=4 の各グリッド点、各スケール σ ∈ {3,6,12,24,48,96} で
   「中心の平滑値 − 半径 2.5σ の円周 16 方向の平滑値」を求め、小さい方から 2 番目を落差とする
   （ミニブロは枝 1 本でつながっているので 1 方向の非降下を許容する）
   画像外・未計算の方向は落差 0 として扱う（端で尾根がピークに化けるのを防ぐ）
   - `peak{σ}` = 落差そのもの（画面の値域に対する大きさ）
   - `contrast{σ}` = 落差 ÷ 半径 2.5σ の箱内の標準偏差（z=4 で飽和）。画面全体では小さくても
     周囲より明確に浮き出た小さな構造（花びら型の中心など）を拾う
  ↓
4. 合成スコア = max(Σ weight × √value, 4 × √junction)。weight はスケール i に対して 0.5 + 0.25 i
   （contrast も同じ重み）。粗いスケールほど重く、複数スケールで一貫してピークになる大きな構造を優先する。
   `junction` は加算ではなく max で合成し、ピークではない結節を候補にしつつ強いピークを底上げしない
  ↓
5. 8近傍の局所最大を候補にする → 最大値×0.3 で足切り
  ↓
6. 順位付け専用 feature `symmetry` の極大点に最も近い候補 1 つに 2 × √value を加算
   （盤面の対称中心は小さなピークでしかないことが多いので、順位だけ押し上げる。足切りには影響しない）
  ↓
7. スコア順に、候補自身の支配的スケールに応じた半径で NMS → 最大 12 件
   （広い丘の上にある小さく鋭いピークは別物として残す）

### `junction` feature（線の交点らしさ）

各グリッド点について半径 8/16/32px の円周上の平滑値（36 サンプル）を取り、プロミネンス（円周の sd × 0.5）以上の
山の数を「その点から放射する線の本数」とみなす。全半径で 3 本以上なら交点で、値 = 振幅ゲート（sd 0.03 で 1.0）×
min(1, (本数 − 2) / 2)。線 1 本の上は 2 本、平坦部は 0 本なので 0 になる。
s17 Sixfold Sigil の軸上の結節や s19 Beacon Spire の星型コピーのような、iteration の鞍点にある構造を拾う。

### `symmetry` feature（対称中心らしさ）

16px 間隔のグリッド点について、半径 0.1〜0.4 × 短辺の円周上で平滑化した値の並び（90 サンプル）を取り、
n=3〜9 回転対称の相関を測る: k/n 回転（k=1..n−1）での相関の平均から、その中間の回転での相関の平均を引く
（滑らかなだけの分布はどちらも高く、n 回対称なら前者だけ高い）。完全対称で 2 になるので 2 で割る。
円周の値の振幅（標準偏差 0.05 で 1.0）を掛けて小さなうねりの偶然の周期性を抑え、上位 2 半径の平均を採る。
n=2 は直線が通るだけで成立するので使わない。
```

## 指標の追加

スコアマップは `ScoreFeature`（名前・スケール・重み・グリッド値）の集合で、合成スコア = Σ weight × √value。
現状は `peak{σ}`・`contrast{σ}`（加算）、`junction`（standalone: max 合成）、`symmetry`（rankOnly: 順位付けのみ）。
別の指標を足すときは `computeScoreMap` で feature を 1 つ追加する。
デバッグUIのヒートマップには feature 名でそのまま出る。

## 検証

`pnpm eval:ip`（`eval/` 以下）。ブラウザ不要で `scenes.json` のシーンの iteration buffer を node 上で計算し
（初回のみ、以後 `tmp/ip-eval/cache/`）、`expected.json` の期待点と突き合わせたレポート `tmp/ip-eval/report.md` と
検出結果を重ねた PNG（`sNN.png`, `sNN-heatmap.png`）を出力する。
期待点は目視で作ったものなので、結果を見て適宜直す。

## パフォーマンス

800×800 で約 140ms（node、単スレッド）。バッチ計算完了時に Worker で 1 回だけ実行する。
